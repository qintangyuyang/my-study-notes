## 二、值类型与引用类型、栈与堆

> 纠错点（摸底第 8 题）：引用类型变量**本身**存储在栈上，只有实例在堆上。当时答错成「栈，堆，堆」——第二空应为「栈」。

### ① 概念总结

**Q：哪些是值类型？哪些是引用类型？**
值类型：int、float、double、bool、char、enum、struct；引用类型：class、数组、List、string、委托、接口、object。

**Q：分别存储在哪里？**
值类型变量直接存在**栈**上；引用类型变量本身存在**栈**上（存的是地址）；`new` 出来的实例存在**堆**上。

**Q：string 是哪种类型？有什么特殊之处？**
string 是**引用类型**，但内容**不可变**：任何「修改」操作都会创建新字符串对象，原对象不变。正因不可变，它用起来像值类型，最容易混淆。

### ② 最小可运行示例（代码：csharp/exercises/week01/ValueRefDemo.cs）

- 现象 A（值类型复制值）：`int: a=10, b=20`；`struct: s1.X=1, s2.X=99` —— 改副本不影响原变量
- 现象 B（引用类型共享实例）：`class: c1.X=99, c2.X=99` —— 两个变量指向同一个堆上实例，一个改全变
- **结论**：值类型赋值复制**值本身**；引用类型赋值复制**地址**（栈上的引用），共享同一个堆上实例

### ③ 踩坑记录

| 坑 | 原因 | 解决 |
|---|---|---|
| 以为 class 实例赋给新变量后是两个独立对象，结果改一个另一个也变 | 引用类型赋值只复制栈上的地址，不复制堆上的实例 | 需要独立副本时显式 new 一份或写 Clone 逻辑 |

## 三、继承与多态

> 纠错点（摸底第 14 题）：把「多态」答成了「继承」。
> - 继承 = 子类复用父类成员（怪物继承基类、各有属性 → 这是继承）
> - 多态 = 父类引用指向子类对象时，调用的是**子类**的方法

### ① 概念总结

**Q：继承解决什么问题？**
代码复用 + is-a。共同属性/方法放基类，子类直接用，避免重复逻辑（如怪物基类实现扣血、攻击逻辑）。

**Q：多态解决什么问题？**
同一套代码能处理不同子类，调用方只依赖基类、不知道具体类型，新增子类不用改调用方代码（开闭原则）。例：`List<Enemy>` 统一遍历调用 `TakeDamage()`；`Feed(Animal)` 任何动物都能传。

**Q：virtual / override / base 分别是什么？**
virtual = 允许子类覆盖；override = 子类覆盖父类实现；base = 子类里调用父类被覆盖的方法（`base.Method()`，Unity 里常见 `base.Awake()` / `base.Start()`）。

**Q：为什么 `Animal a = new Dog(); a.Speak()` 会调 Dog 的实现？**
virtual + override 使调用在**运行时**按对象真实类型分派（运行时绑定）；去掉它们就是**编译期**按声明类型绑定，只调 Animal 的实现。

### ② 最小可运行示例（代码：csharp/exercises/week01/AnimalDemo.cs）

- 结果：`汪汪` / `喵喵`（引用声明为 Animal，却调出了子类实现——多态生效）
- 实验：去掉 virtual/override 后输出「动物在叫」「动物在叫」→ 编译期绑定，只看声明类型

### ③ 踩坑记录

| 坑 | 原因 | 解决 |
|---|---|---|
| 去掉 virtual/override 后，`Animal a = new Dog()` 调 Speak 输出「动物在叫」 | 没有 virtual/override 是编译期绑定，按声明类型（Animal）绑定 | 需要多态时父类加 virtual、子类加 override，才能运行时按真实类型分派 |

## 四、异常处理与 finally

> 纠错点（摸底第 18 题）：finally 的关键点是「**无论是否抛出异常都会执行**」，当时只写了「最终需要执行的一步」。

### ① 概念总结

**Q：try / catch / finally 各自的作用？**
`try`：把可能抛异常的代码包起来，异常发生时程序不崩溃。
`catch`：捕获 try 抛出的异常并处理——打印日志、给默认值、回退状态、提示用户。
`finally`：无论 try 是否抛异常、是否被 return，都会最后执行，放释放资源的收尾代码。

**Q：finally 什么时候执行？什么极端情况不执行？**
正常/异常/return 三条路径都会执行；但进程被杀、`Environment.FailFast`、StackOverflow 等极端情况不保证执行。

**Q：抛出异常后的执行流程？**
try 里异常点**之后**的代码直接跳过 → 跳到 catch → 最后走 finally。

**Q：什么时候该捕获、什么时候该向上抛？**
能处理就捕获（就地恢复/兜底），处理不了就向上抛；**绝不空捕获吞掉异常**。

### ② 最小可运行示例（代码：csharp/exercises/week01/TryCatchDemo.cs）

- 实验 1：try 开始 → 抛 NullReferenceException → catch 捕获 → finally 执行（「这行不会执行」确实没打印）
- 实验 2：catch 里 `return` → finally **依然执行**（return 挡不住 finally：先准备返回值 → 执行 finally → 才真正返回）

### ③ 踩坑记录

| 坑 | 原因 | 解决 |
|---|---|---|
| 以为 catch 里 return 后 finally 就不执行了 | finally 在方法返回路径上被强制执行 | 资源释放必须放 finally；别在 catch 里写空逻辑藏错误 |
